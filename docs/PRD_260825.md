### 2.3 通用推理标签解析器

**问题**：模型将思考内容放在 `content` 字段的标签对中（如 `<think>...</think>`），原逻辑把所有 `content` 当作回复内容。

**解决方案**：[session_manager.py](../benchscope/session_manager.py) 新增 `parse_think_tags(raw)` 函数，支持多种常见推理标签对：

| 类别 | 支持的标签对 |
| --- | --- |
| 标准 ASCII | `<think>` / `<reasoning>` / `<thinking>` / `<reflection>` / `<analysis>` |
| 全角版本 | `＜think＞` / `＜reasoning＞` / `＜thinking＞` |

**流式解析**：每收到一个 token 就重新解析累积的 `raw_content`，将思考部分作为 `{"thinking": ...}` 事件、回复部分作为 `{"token": ...}` 事件分别发送。

**兼容旧消息**：`_restore_sessions` 检测 content 中是否包含任一已知推理标签，自动拆分 thinking + content。

### 2.4 顶部性能数据栏

| 指标 | 计算方式 |
| --- | --- |
| turns | 会话总轮数 |
| steps | 会话总步数 |
| LLM | 自用户发送以来的累计耗时（秒） |
| TTFT avg | 首 token 延迟（秒） |
| Output tok/s | 生成速度 |
| TPOT ms | 每输出 token 耗时 |
| ITL ms | token 间平均延迟 |

- 流式期间实时更新（每个 token 到达时计算）
- 结束时存入 `activeSession._perf` 并 PATCH 后端持久化
- 格式：`turns · steps | LLM | TTFT · tok/s | Output tok/s | TPOT ms | ITL ms`

### 2.5 底部操作栏重构

| 元素 | 实现 |
| --- | --- |
| 模型选择器 | `a-select` 无边框，值存 localStorage |
| 对话质量 | 新增 High/Medium/Low 选择（映射 temperature：0.9/0.5/0.2） |
| 思考开关 | `a-switch`，控制请求是否传 `chat_template_kwargs.enable_thinking` |
| 发送按钮 | 文字按钮，有内容时蓝色可点 / 无内容时灰色不可点 |

### 3.2 会话管理

| 变更 | 说明 |
| --- | --- |

| stream_chat 通用解析 | 每 token 调用 `parse_think_tags` 增量分离 |

### 3.3 API 端点

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/tasks/{task_id}` | 获取任务完整快照（含 rows） |

## 7. 已知限制

| 限制 | 说明 |
| --- | --- |
| 流式解析性能 | 每 token 重新解析整段 content，O(n²) 复杂度，常规对话量级可接受 |
| 旧任务无 full.log | 功能上线前创建的任务无 full.log 文件，详情页终端为空 |
| 全角标签覆盖 | 当前支持 think/reasoning/thinking 全角版本，其他标签可按需扩展 |
| 服务需非沙箱模式 | 会话/任务持久化目录 `/root/.benchscope/` 需在非沙箱环境下读写 |
