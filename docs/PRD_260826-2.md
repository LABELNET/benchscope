## 1. 任务双模式（并发 / 阈值）

### 1.1 后端快照

- `task_manager.py`：任务快照新增字段
  - `mode`：`concurrency`（默认）或 `threshold`；
  - `tpot_threshold_ms`：阈值模式必填，正整数；
  - `output_throughput_threshold`：阈值模式整数（0 表示不限）。
- 并发模式 `concurrency_list` 取用户配置的请求数列表（多档并发压测）；阈值模式固定 `concurrency_list = [1]`，以「逐渐增加请求数直至不满足阈值」为目标（单请求逐级探测），命令预览仅展示首条探测命令并提示执行策略。
- `test_manager.py`：mode 与阈值字段随任务创建透传；命令预览在阈值模式下仅输出首条命令。

### 1.2 前端入口

- 新增 `PerfCreateView.vue` 独立创建页（路由 `/performance/create`），顶部含返回箭头与 Mode 标识；
- 三步表单：
  - Step1 条件：`BaseEnvPanel`（模型/框架/Base URL）+ `ConditionPanel`（数据集、输入输出长度；并发模式编辑请求数列表，阈值模式编辑 `tpotThreshold` 与 `outThroughput`）；
  - Step2 参数：`ParamGroupPanel` 按框架（vLLM / SGLang）编辑 params.yaml；
  - Step3 预览：实时生成创建命令，阈值模式附执行策略提示。

## 2. Cases 面板（阈值模式）

- 面板标题区只读展示阈值条件：`TPOT mean ≤ {tpot_threshold_ms} ms`、`Output token throughput ≤ {output_throughput_threshold} tok/s`（0 显示为「不限」）；并发模式不展示条件。
- 每个 case（如 `256x256`）独立展示请求状态：
  - 已执行 / 执行中组：展示完整测试请求列表（不再折叠为 done 标签），进行中请求蓝色标记，已完成请求绿色标记；
  - 未执行组：整组显示 Pending；
- 阈值模式下 case 状态由「该 case 已完成的并发档位 + 当前执行中的并发档位」合并计算，不依赖全局执行进度（各 case 互不联动）。

## 3. Realtime Data 表格（分组与高亮）

### 3.1 分组与排序

- 表格按 `label`（case）分组，分组依据后端实时行与快照 label 匹配；
- 组头以扁平行（`record.group = true`）插入 `tableData`，避免 antd 树表缩进，样式为浅蓝底 + 加粗；
- 每个分组内部独立按「请求数（requests）」升序排列，组间互不影响。

### 3.2 Best / BestPerf 唯一高亮

- **Best**：本地面板阈值（`tpotThreshold` / `outputThreshold`）对组内行逐行判定，满足条件（`tpot_mean <= thr` 且 `output_mean >= thr`，仅 `>0` 的阈值参与判定）的行中，取 **requests 最大的一行** 唯一标记为 Best（高亮行）；
- **BestPerf**：仅阈值模式任务，使用任务快照阈值（`tpot_threshold_ms` / `output_throughput_threshold`），判定策略同上，组内唯一；
- 两阈值均为 0 时不做任何标记；
- 判定为「最优行」的行同时满足 Best 与 BestPerf 时，仅保留 BestPerf 标记（唯一高亮行）。

### 3.3 本地阈值控件

- Realtime Data 面板 extra 区提供两个整数输入：`TPOT Threshold`（默认 100 ms）、`Output Token Threshold`（默认 0 tok/s）；
- 变更后即时重算 Best 高亮，不写回任务、不影响后端；
- 用于「本地试算」：在不改任务的前提下验证不同阈值下的达标行。

## 4. Perf 面板调整

- Framework 行下方新增 **Mode 行**，展示 `threshold`（阈值模式）/ `concurrency`（并发模式），样式与其他信息行一致（不高亮）；
- 移除 Requests 行（该信息由 Cases 面板与 Realtime 表格承载）。

## 5. Successful 百分比整数

- 成功率统一按 `Math.round(ok / total * 100) + '%'` 显示，去除小数。

## 6. Excel 导出

- 前端：MetricsTable footer 新增 **Download**（图标 + 文案）按钮，位于 Columns 右侧；点击后将当前表格（表头 + 行值，含分组行标记）POST 至后端并下载返回文件；
- 后端：`POST /api/tasks/{task_id}/export`
  - `ExportExcelRequest(headers, rows)` 接收前端结构；
  - openpyxl 生成 Workbook：表头加粗；分组行加粗并填充 `E6F4FF`；
  - 文件写入 `task.run_dir / realtime_{task_id}.xlsx`（任务记录缓存目录），并以 `FileResponse` 返回下载；
  - 任务不存在返回 404，导出异常返回 500。

## 7. 表格 footer 布局

- `.table-footer` 由 `space-between` 三子元素改为「左侧行数统计 + 右侧 `.footer-actions` 容器」；
- `.footer-actions` 内依次为 Columns（下拉）→ Download（按钮），两者紧贴面板右下角，顺序固定。

## 9. 测试建议

### 开发模式（FAKE）
- `./scripts/dev.sh` 一键启动 mock OpenAI + FAKE bench 后端 + 前端；
- 走通「创建阈值任务 → Cases 条件显示 → 实时表格分组高亮 → 导出 Excel」。

### 验证模式（真实环境）
- 不带 `BENCHSCOPE_FAKE_BENCH` 启动后端（如 `--port 8081`），Base URL 指向真实推理服务（如 http://127.0.0.1:8000）；
- 创建并发任务与阈值任务各一，验证：Mode 行显示、Cases 独立请求状态、分组表格组内升序、Best/BestPerf 唯一高亮、导出文件位于任务 run_dir。

### 边界用例
- 两阈值全 0：不产生任何高亮；
- 组内无满足阈值的行：该组不标记；
- 多组并行：各组独立判定、互不影响；
- 阈值模式成功率与 TPOT/Output 数值列整数展示。

## 10. 已知限制

- 导出内容为前端当前可见列（受列设置隐藏影响），且为导出时刻快照；
- 分组行以扁平行实现，导出时按 group 标记复现，不保留前端行高亮样式；
- 阈值模式探测策略（`concurrency_list=[1]` 逐级增加）目前为渐进式探测，单任务耗时会随档位增加而变长；
- FAKE 模式数据为仿真输出，仅用于联调，不代表真实性能。
